# План: чат в комнате с игроками

## Можно ли прикрутить?

**Да.** Уже есть всё нужное: Socket.IO, комнаты по коду, список игроков с именами. Чат — это новый тип сообщений в той же комнате.

---

## 1. Что нужно сделать

### Сервер (Node.js + Socket.IO)

- **Событие `chat_message`**  
  Игрок шлёт `{ roomCode, text }`. Сервер проверяет, что сокет в этой комнате, подписывает сообщение именем игрока (из `room.players`), рассылает в комнату: `io.to(roomCode).emit('chat_message', { playerName, text, timestamp })`.
- **Ограничения**  
  - Длина текста (например, до 200–300 символов).  
  - Частота сообщений (анти-спам: не чаще 1 сообщения в 1–2 сек с одного сокета).
- **История (по желанию)**  
  В объекте комнаты хранить последние N сообщений (например, 50). При входе в комнату отдавать историю новому игроку отдельным событием (например, `chat_history`).

### Клиент (веб / APK)

- **UI чата**  
  - Кнопка «Чат» / иконка (в лобби и в игре).  
  - Панель чата: список сообщений + поле ввода + «Отправить».  
  - Панель можно сворачивать (только заголовок «Чат» / иконка) и открывать по клику.
- **Отображение сообщений**  
  Формат: «Имя: текст» или отдельно имя и текст; время по желанию. Скролл вниз при новых сообщениях.
- **Сокет**  
  - При событии `chat_message` добавлять сообщение в список и обновлять UI.  
  - По отправке вводимого текста вызывать `socket.emit('chat_message', { roomCode, text })`.

### Безопасность и модерация

- Санитизация текста на сервере (экранирование HTML/спецсимволов при отдаче или при сохранении), чтобы нельзя было вставить теги/скрипты.
- При желании — фильтр мата (список слов или простой внешний сервис).
- При злоупотреблениях — только удаление из комнаты; полноценный бан потребует хранения состояния (БД/файл).

---

## 2. Порядок внедрения

| Шаг | Действие |
|-----|----------|
| 1 | Сервер: обработчик `chat_message`, проверка комнаты и длины, `io.to(roomCode).emit('chat_message', ...)` |
| 2 | Клиент: блок UI чата (сворачиваемая панель), поле ввода, кнопка, список сообщений |
| 3 | Клиент: подписка на `chat_message`, вывод в список, отправка по кнопке/Enter |
| 4 | По желанию: лимит частоты сообщений на сервере |
| 5 | По желанию: история в комнате + событие `chat_history` при входе |

---

## 3. Где расположить чат в интерфейсе

- **Лобби** — под списком игроков или справа: кнопка «Чат», по нажатию открывается панель.
- **В игре** — угол экрана (например, правый верхний): иконка или кнопка «Чат», панель поверх игры (overlay) или сбоку, не перекрывая карты и кнопки действий.

На мобильных панель чата лучше открывать на полный экран или на полэкрана (снизу/сбоку), чтобы не мешать игре.

---

## 4. Оценка по времени

- Минимальный чат (без истории, без модерации): **1–2 часа** (сервер + клиент).
- С историей и лимитом сообщений: **+0.5–1 час**.
- Удобный UI (сворачивание, скролл, мобильная верстка): **+1–2 часа**.

---

## 5. Итог

Прикрутить чат в текущую архитектуру можно без смены стека: только новые события Socket.IO и блок в UI. Начать разумно с простого варианта (отправка/приём в реальном времени), затем при необходимости добавить историю и ограничения.
